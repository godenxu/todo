# 演示 / 测试数据说明

这份 `科技规划处工作管理.json` 是**造出来的假数据**，专门用于在测试环境里把系统的每个功能都点一遍。
处里同事的姓名照旧沿用（方便对号入座），另外虚构了 5 位同事把人数撑起来；所有工作、任务、里程碑、
日志的内容都是编的，**跟真实业务无关**。

> ⚠️ **千万不要把这个文件放进生产共享文件夹。**
> 它一进去就会跟大家几个月的真实数据合并，收不回来。测试请另建一个共享文件夹。
>
> ⚠️ **光换文件夹还不够。** 浏览器的本机缓存（localStorage）里存着上一次的数据，
> 一台平时连生产文件夹的电脑直接去连演示文件夹，程序会把两边**合并**——这正是它该做的，
> 于是假数据就进了真实数据里。**这件事真发生过一次。**
> 所以第一节第 5 步"先断开、清空本机数据，再连测试文件夹"不能跳过。
>
> **万一已经混进去了**：跑一次盘点。它只读、不改任何东西，会照着生成器里那份"哪些是造出来的"名单
> 把假数据一条条列出来，并给出清理顺序：
>
> ```bash
> node tools/audit-demo-mix.js  路径/科技规划处工作管理.json
> ```

## 一、怎么用

1. 新建一个**测试专用**的共享文件夹，例如 `D:\系统测试\`（不要用处里日常那个）。
2. 把本目录的 `科技规划处工作管理.json` 拷进去。
3. 单独复制一份 `index.html` 到测试机（或用同一份都行），用 Chrome / Edge / 360 极速模式打开。
4. 页面提示连接共享文件夹时，**选刚建的那个测试文件夹**。
5. 登录界面会列出下面这些账号，PIN 见第二节。

如果这台浏览器之前连过生产文件夹、本地还缓存着真实数据，先在数据页把共享文件断开、清空本机数据，
再连测试文件夹；否则本机那份真实数据会跟演示数据合并到一起。

**换回生产环境**：断开测试文件夹 → 清空本机数据 → 重新连接生产共享文件夹。
连接生产文件夹之前，务必先把生产的 `科技规划处工作管理.json` 另存一份备份。

## 六、重新生成

数据里的"逾期""今日到期""本期已交付"这些是按**生成当天**算的相对日期。放上一两个月再用，
日期就飘了，重新跑一次即可（需要装了 Node.js）：

```bash
node tools/gen-demo-data.js
```

生成完顺手自检一遍（会把每一页、报告页每个周期、图表页每个分页都渲染一遍，任何一处报错就算不合格）：

```bash
node tools/verify-demo-data.js
```

也可以直接生成到别的位置：

```bash
node tools/gen-demo-data.js D:/系统测试/科技规划处工作管理.json
```

生成器用的是固定随机种子，同一天跑多少次结果都一样；换一天跑，日期整体平移，形状不变。

## 七、万一演示数据混进了真实数据

跑这个盘点（**只读，不改任何东西**）：

```bash
node tools/audit-demo-mix.js  路径/科技规划处工作管理.json
```

它会把假数据分三档列出来：

- **确定是造出来的**：挂在虚构工作下的，或者标签是"重点/攻坚/常规"的
  （这条判据来自实测——处里真实数据的标签一直是"测试"或空，从没用过这三个）
- **高度疑似**：标题正好套用了生成器那 12 个模板之一，但标签为空
- **真实任务被填上了虚构人员**：任务本身是真的，把人名改回来就行，别整条删

如果同目录下有演示数据混入**之前**导出的备份，脚本会自动拿它当锚点——凡是备份里就有的记录一律算真实，
这是最硬的证据。它还会自己判断哪些备份已经被污染、不能当基准（那种备份当锚点会把污染全认成真实的）。

最后它会打印一份清理顺序。刻意不提供"一键删除"：删的是共享文件里全处的数据，不该由一个命令行脚本代劳。
